# YeeHaw Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build YeeHaw, a small, polished macOS 27.2+ menu bar manager. It hides apps' menu bar
icons into a glass strip, reorders visible icons through a layout window, and adjusts icon
spacing.

**Architecture:**
- **Swift package with two targets:**
  - `YeeHawCore` holds all the logic and talks to the system only through protocols, so it can be
    unit-tested with fakes.
  - `YeeHaw`, the app target, holds the system adapters (Accessibility, CFPreferences with
    security-scoped bookmarks, ScreenCaptureKit, relaunching apps) and the AppKit/SwiftUI
    interface.
- **Building the app:** `scripts/build-app.sh` assembles a signed `.app`. This is the same pattern
  as `~/GitHub/zStats`.

**Tech Stack:**
- Swift 6.2 tools, Swift Testing, SwiftUI plus AppKit
- Accessibility (`AXUIElement`), CFPreferences, ScreenCaptureKit, ServiceManagement (`SMAppService`)
- No third-party dependencies

**Spec:** `docs/superpowers/specs/2026-10-31-yeehaw-design.md` (approved 2026-10-31). Read it
before any task. Its "How macOS 27 works, and what was proven" section holds the file paths, plist
formats, and proven techniques that this plan only references.

## Global Constraints

- Minimum OS: macOS 27.2. Use `platforms: [.macOS("27.2")]`, `LSMinimumSystemVersion` `27.2`, and
  a launch-time check that shows a clear message and quits on anything older.
- Bundle ID `com.zapps.yeehaw`. `LSUIElement` is true, so there's no Dock icon.
- Sign with team `V2P99VF75Q` (`codesign --sign V2P99VF75Q --options runtime --timestamp`), and
  refuse any certificate from another team. Notarize with
  `xcrun notarytool submit --keychain-profile notary --wait`.
- Never commit a certificate identity name or any personal name; refer only to the team ID.
- Dev builds are always signed with the team certificate, never ad hoc, and run from
  `~/Applications/YeeHaw.app`. Ad-hoc rebuilds lose the Accessibility grant, and macOS won't list
  apps that run from `/private/tmp`.
- Not sandboxed.
- No code copied from Thaw (GPLv3).
- Positions are written only on a user edit, plus the temporary reveal slot, which is always
  restored. There are no timers or reactions that rewrite order on their own.
- Never relaunch `com.apple.*` processes or apps whose bundle isn't in an Applications folder.
  Never force-quit anything. Never restart `MenuBarAgent`.
- Apps the user switched off in System Settings (off, and not in the journal) never appear in any
  YeeHaw surface and are never switched on by YeeHaw.
- Visual bar: native macOS 27 look, with Liquid Glass materials, SF typography, spring motion, and
  correct light and dark appearance. Respect Reduce Motion and Reduce Transparency. Nothing
  placeholder-looking ships.

## Review Focus

1. **YeeHaw crashes, or is killed, while an icon is revealed.** The app is left switched on and its
   position slot is temporary. The next launch should restore the original position value and hide
   the app again. Tested in Task 6.
2. **A revealed app's menu or popover never sends a close signal** (popover apps, Space switches,
   apps that open a window). The app should be re-hidden after an outside click or a 30 s
   inactivity timeout, never left revealed for good. Tested in Task 8.
3. **A hidden app quits and relaunches,** or launches after YeeHaw. Its Allow entry stays off, so it
   should stay hidden, with no repeated flipping and no state churn. Tested in Task 6.
4. **The file grant goes stale or is revoked,** for example because the bookmark won't resolve or a
   read is refused after cfprefsd replaces the file. YeeHaw should mark that file as needing a new
   grant, show it in Settings and the strip, and stop writing. It must not crash or retry in a loop.
   Tested in Task 5.
5. **The position table holds stale or duplicate keys** for apps that aren't running, such as both
   `com.google.drivefs::Google Drive` and `::Item-0`. A reorder must preserve every key it doesn't
   own, and must write all of an item's existing keys. Tested in Task 3.

### Task 3: Position table and placement math

**Files:**
- Create: `Sources/YeeHawCore/PositionTable.swift`, `Sources/YeeHawCore/PositionKey.swift`
- Test: `Tests/YeeHawCoreTests/PositionTableTests.swift`, `Tests/YeeHawCoreTests/PositionKeyTests.swift`

**Interfaces:**
- Produces:
  ```swift
  public struct PositionTable: Equatable {
      public var values: [String: Double]              // TrailingItemPreferredPositions
      public init(_ values: [String: Double])
      public static let minimumGap: Double = 1.0
      /// Changed entries only. `leftNeighbor` has the larger value; nil = moving to the far left.
      /// `rightNeighbor` nil = immediately left of module:Clock (value 0).
      public func placement(of keys: [String], leftNeighbor: String?, rightNeighbor: String?) -> [String: Double]
      /// A value immediately left of `key`: midpoint to the next larger value, or value(key) + 20 if none.
      /// Used for the reveal slot and for placing YeeHaw's own icon.
      public func slotValue(leftOf key: String) -> Double
  }
  public enum PositionKey {
      /// All table keys for one item: existing ones first; if none exist, one new key.
      public static func keys(bundleID: BundleID, axIdentifier: String, indexInApp: Int, table: PositionTable) -> [String]
      public static let controlCenter = "module:BentoBox-0"
      public static let clock = "module:Clock"
  }
  ```

The spec's Technique 3 fixes the semantics: a larger value sits further left, and Clock is 0.
`keys` returns every existing key with the prefix `status:<bundleID>::` whose name equals
`axIdentifier` (if not empty) or `Item-<indexInApp>`. Otherwise it returns
`status:<bundleID>::<axIdentifier or Item-indexInApp>`. Every key for an item gets the same value.

Placement algorithm, which the signature alone doesn't determine:
```
L = value(leftNeighbor) ?? (max of all values + 20)
R = value(rightNeighbor) ?? 0
if L - R >= 2 * minimumGap: v = (L + R) / 2; return keys → v
else: v = R + minimumGap; then walk existing entries in ascending value order starting at
      leftNeighbor: each entry whose value < previous + minimumGap is raised to previous + minimumGap
      (cascade stops at the first entry already far enough). Return keys → v plus every raised entry.
```

- [ ] **Step 1:** Write the tests, using values from the owner's real table:
  - `placesBetweenNeighbors`: a table with DigUp 375.5 and fiddle 409.5; move DigUp between
    `status:edu.umontana.fiddle::Item-0` (left) and `status:com.google.Chrome::Item-0` (248) →
    `["status:com.abdurrahim.DigUp::Item-0": 328.75]`, and fiddle is untouched
  - `farLeftUsesMaxPlus20`: `leftNeighbor: nil` → max + 20
  - `tightGapCascades`: right neighbor at 10.0, left neighbor at 10.5, and another entry at 11.2 →
    the moved item gets 11.0, the left neighbor becomes 12.0, and the 11.2 entry becomes 13.0
    (every change returned, nothing else)
  - `preservesForeignAndStaleKeys`: a placement never returns or drops keys for other bundles
    (Review Focus 5)
  - `slotLeftOfYeeHaw`: YeeHaw at 130 and the next larger value at 144 → `slotValue(leftOf:) == 137`.
    With nothing larger → 150.
  - PositionKey tests:
    - `keysPrefersExistingDuplicates`: the drivefs table with both `::Google Drive` and

    - `keysUsesIdentifier`: `com.malwarebytes.mbam.frontend.agent` with identifier
      `statusBar.icon.alert` → that key
    - `keysNewWhenMissing`: `com.zapps.yeehaw`, "", 0, empty table →
      `["status:com.zapps.yeehaw::Item-0"]`

### Task 5: Hiding state and reconciliation rules

**Files:**
- Create: `Sources/YeeHawCore/HidingState.swift`
- Modify: `Sources/YeeHawCore/Ports.swift` (add `StateStoring`)
- Test: `Tests/YeeHawCoreTests/ReconcilerTests.swift`

**Interfaces:**
- Produces:
  ```swift
  public struct PendingReveal: Codable, Equatable, Sendable { public var bundleID: BundleID; public var originalPositions: [String: Double?] }
  public struct HidingState: Codable, Equatable, Sendable {
      public var hidden: [BundleID]          // strip order
      public var journal: Set<BundleID>      // apps YeeHaw switched off
      public var pendingReveal: PendingReveal?
      public var needsGrant: Set<GrantedFile>
      public static let empty: HidingState
  }
  public enum GrantedFile: String, Codable, Sendable { case allowList, positions }
  public enum AllowAction: Equatable, Sendable { case switchOn(BundleID), switchOff(BundleID) }
  public enum Reconciler {
      public static func onLaunch(_ s: HidingState, allow: AllowSnapshot) -> (actions: [AllowAction], restorePositions: [String: Double?], state: HidingState)
      public static func onQuit(_ s: HidingState) -> (actions: [AllowAction], state: HidingState)
      public static func hide(_ id: BundleID, _ s: HidingState, allow: AllowSnapshot) -> (actions: [AllowAction], state: HidingState)
      public static func show(_ id: BundleID, _ s: HidingState) -> (actions: [AllowAction], state: HidingState)
      public static func externalChange(_ s: HidingState, before: AllowSnapshot, after: AllowSnapshot) -> HidingState
      public static func userOwnedOff(_ s: HidingState, allow: AllowSnapshot) -> Set<BundleID>   // off and not journaled
      public static func adopt(_ ids: [BundleID], _ s: HidingState) -> HidingState
  }
  public protocol StateStoring: Sendable { func load() -> HidingState; func save(_ s: HidingState) }
  ```

The rules come from the spec's "State, ownership and edge cases" section:
- `onLaunch`: switch on every journaled app that isn't in `hidden`; switch off every app in
  `hidden` that's on; restore and clear `pendingReveal`; drop from `hidden` any app no longer
  tracked.
- `onQuit`: switch on everything journaled, and clear the journal. There's no power-off function,
  because power-off does nothing.
- `hide`: only for tracked apps that are on. It adds the app to `hidden` and `journal`.
- `externalChange`: an app in `journal` that flips to on is removed from `hidden` and `journal`.
  An app the user switches off simply becomes user-owned.

  - `hideRefusesUntracked`: `hide("X")` with X not in the snapshot → no actions, state unchanged

  - `userOwnedOffExcludesJournal`: allow {U: false, A: false, V: true}, journal {A} → {U}
  - `adoptAddsToHiddenAndJournal`

### Task 6: MenuBarController (the coordinator)

**Files:**
- Create: `Sources/YeeHawCore/MenuBarController.swift`
- Modify: `Sources/YeeHawCore/Ports.swift`
- Test: `Tests/YeeHawCoreTests/MenuBarControllerTests.swift` (with fakes for every port)

**Interfaces:**
- Consumes: Tasks 2–5
- Produces:
  ```swift
  public protocol PreferencesFile: Sendable {
      func read(_ key: String) throws -> Any?          // throws GrantError.needsGrant when access fails
      func write(_ key: String, _ value: Any) throws
  }
  public enum GrantError: Error { case needsGrant(GrantedFile) }
  public protocol MenuBarReading: Sendable { func items() async -> [MenuBarItem] }
  public protocol Sleeper: Sendable { func sleep(seconds: Double) async }
  public enum ControllerError: Error, Equatable { case notTracked(BundleID), notHonored(BundleID), needsGrant(GrantedFile) }

  @MainActor public final class MenuBarController {
      public init(allowFile: PreferencesFile, positionFile: PreferencesFile, reader: MenuBarReading, store: StateStoring, sleeper: Sleeper)
      public private(set) var state: HidingState
      public private(set) var items: [MenuBarItem]                    // last read, drawn only
      public static let honorTimeout: Double = 5.0
      public static let pollInterval: Double = 0.05
      public func launch() async throws
      public func refresh() async                                     // re-read items
      public func hide(_ id: BundleID) async throws
      public func show(_ id: BundleID) async throws
      public func move(_ item: MenuBarItem, leftNeighbor: MenuBarItem?, rightNeighbor: MenuBarItem?) throws
      public func reorderHidden(_ ids: [BundleID])
      public func beginReveal(_ id: BundleID, nextTo yeehaw: MenuBarItem) async throws -> MenuBarItem   // returns the drawn item
      public func endReveal() async throws
      public func allowListChanged() throws
      public func quit() throws
      public func userOwnedOff() throws -> Set<BundleID>
      public func adopt(_ ids: [BundleID]) async throws
  }
  ```

Behaviour:
- **Every flip:** read the Allow list, apply it with `AllowList.setAllowed`, and write it back.
  Then poll `reader.items()` every 50 ms until the item appears (or disappears), for up to 5 s.
  If it doesn't, throw `.notHonored`; there is no retry loop.
- **Saving state:** persist through `store.save` *before* each flip, so a crash leaves the journal
  correct.
- **`beginReveal`:**
  1. Save `pendingReveal` with the item's current position values.
  2. Write `slotValue(leftOf:)` of YeeHaw's key to every key of the item.
  3. Switch the app on and wait until it's drawn.
- **`endReveal`:** switch the app off, wait until it's gone, restore the original positions, and
  clear `pendingReveal`.
- **`GrantError`:** when the Allow file or position file throws it, add the file to
  `state.needsGrant`, save, and throw `.needsGrant` (Review Focus 4).

- [ ] **Step 1:** Write the tests. Use a `FakeMenuBar` that holds an Allow snapshot plus a position
  table and derives `items()` from them, so a flip shows up on the next poll; a fake that ignores
  writes simulates `.notHonored`.
  - `hideFlipsAndWaits`: after `hide(A)`, A isn't in `items` and the state has A in hidden and
    journal
  - `hideNotHonoredThrowsWithoutRetry`: the fake ignores writes → throws `.notHonored(A)` after the
    5 s budget measured by a fake clock, with exactly one write
  - `stateSavedBeforeFlip`: the store's save count goes up before the fake sees the write
  - `revealUsesSlotLeftOfYeeHawAndRestores`: `beginReveal`, then `endReveal` → the position table
    equals the original, and A is off
  - `crashMidRevealRecoveredOnLaunch` (Review Focus 1): call `beginReveal`, drop the controller,
    then build a new one over the same fakes and store and call `launch()` → the table is restored
    and A is off
  - `grantFailureMarksNeedsGrant` (Review Focus 4): `allowFile.read` throws
    `.needsGrant(.allowList)` → `hide` throws `.needsGrant(.allowList)`,
    `state.needsGrant == [.allowList]`, and no write is attempted
  - `moveWritesAllKeysOfItem`: an item with two existing keys → both get the same new value
- [ ] **Step 2:** Run `swift test --filter MenuBarControllerTests`. Expected: it fails to compile.
- [ ] **Step 3:** Implement the ports and `MenuBarController`.
